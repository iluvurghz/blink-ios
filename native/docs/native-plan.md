# Blink Native: стек и план (Android + iOS)

Черновик 2, 11.11.2026. Код лежит в `native/` этого репо (`blink-ios`), позже переименуем в `blink-mobile`.

## Коротко

1. **Android:** Kotlin + Jetpack Compose + Media3 (ExoPlayer + MediaSession).
   **iOS:** Swift + SwiftUI + AVFoundation (AVPlayer) + фоновые загрузки через `URLSession`.
   Внутри нет ни WebView, ни Capacitor, ни Tauri.
2. **Бэкенд не трогаем.** Приложения ходят в тот же `blinkmusic.cc/api` и Supabase, что и сайт с ПК-версией.
   Новое для офлайна: `GET /api/offline/resolve` (его делает тред «офлайн-кэш»). Пока он не на проде, клиент сам падает на `GET /api/play/:uuid`.
3. **Офлайн делаем один раз, по одной спецификации** (контракт v1 и поправки от треда офлайна):
   `.part` + докачка по Range + проверка файла + атомарный commit + манифест.
   На каждой платформе нативный движок, одинаковое поведение держат одинаковые тест-кейсы.
4. **Без Mac.** Android собирает GitHub Actions на Linux (и тут же запускает APK в эмуляторе), iOS собирается на macOS-раннере в неподписанный `.ipa`
   (подпись вашим бесплатным сертификатом, как сейчас с `ipa-3`).

## Почему именно так

| Вариант | Вердикт |
|---|---|
| Kotlin + Compose и Swift + SwiftUI (два нативных UI) | Берём. Настоящий нативный UI, лучшая связка с системой: шторка и экран блокировки, CarPlay и Android Auto, виджеты, фон. |
| Kotlin Multiplatform + Compose Multiplatform | Нет. UI на iOS рисует Skia, а не система. Kotlin/Native на macOS-раннере собирается долго, а минуты macOS стоят ×10. |
| Flutter, React Native | Нет. Это не то «нативное», которое вы просите. |
| Capacitor / Tauri Mobile (как `ipa-3` сейчас) | Нет. WebView: лаги на iPhone, фон и аудио капризные. |
| Общее ядро на Rust (UniFFI) | Позже. `core/blink-room` подключим для комнаты (M3). Для M0 дублировать пару сотен строк офлайн-движка дешевле, чем тащить кросс-компиляцию и FFI в обе сборки. |

Версии пинуем на проверенный набор: Gradle 8.14.3, AGP 8.13.0, Kotlin 2.2.21, Compose BOM 2025.09.01, Media3 1.8.0, Coil 3.3.0, OkHttp 4.12.0 (compileSdk/targetSdk 36, minSdk 26);
iOS 17+, Swift 5-режим, XcodeGen. Поднимаем по одной штуке, когда зелёная сборка это подтверждает.

## Как устроен код

| Папка | Что |
|---|---|
| `native/android/core` | Чистая JVM-логика без Android: загрузчик, менеджер очереди, клиент API, вход, LRC, логика экранов (поиск, статус Blink+, очередь без сети). Тесты идут за минуту на любом Linux. |
| `native/android/app` | Приложение: Compose-экраны, плеер в `MediaSessionService`, сервис загрузок, безопасное хранение сессии. |
| `native/android/preview` | Просмотр экранов на компьютере для скриншотов (только в облаке). |
| `native/ios` | Пакет `BlinkCore` (то же ядро на Swift, тесты идут на Linux) и SwiftUI-приложение. |
| `native/design` | Общие шрифты, значки и цвета Blink для обеих платформ. |
| `native/tools` | Поиск публичного ключа входа, проверка APK в эмуляторе. |

## Что берём из текущего приложения

- **API.** Карта эндпоинтов лежит в `native/docs/api-map.md`. Всё снято с `server.js` и веб-клиента, ничего не придумано.
- **Форма трека.** Те же поля и те же `id` (`String(trackId)`, `b:<uuid>`, `cr<id>`), чтобы лайки и плейлисты синхронизировались с сайтом и ПК.
- **Supabase.** Вход, синк библиотеки, каталог артистов (`lic_tracks`), `/api/play/:id` для лицензионных треков.
- **Дизайн.** Токены с сайта: фон `#0d0c10`, текст `#eee9e2`, коралловый акцент `#f8814f`, Unbounded для заголовков, Manrope для текста, нижняя плашка-пилюля, мини-плеер-пилюля.
- **Алгоритмы.** Вспышка (`wave.js`) и LRC-парсер портируем (M2). LRC уже в ядре.

Не берём: Electron/IPC, IndexedDB, цепочку Cobalt/YouTube-iframe (на мобилке источник даёт сервер), WebGL-фон `AuraGL` (заменим нативными градиентами/шейдером).

## Офлайн, который реально работает

**Почему сейчас «Сохранено 0 из 1».**
`offline.js:59-65` для обычного трека (iTunes/Яндекс/чарты) ищет файл только через `findMp3` → `/api/mp3/search`.
Сервер на этот запрос отвечает `503 parser_disabled`, потому что парсер выключен админкой (`server.js:117-120`).
Проигрывание идёт другим путём (`player.js:975-1155`): сначала APIBlink, а скачивание этот путь не использует.
Поэтому играет всё, а сохраняются только лицензионные треки.

**Что решено (контракт v1, поправки 1 и 2).**
- **Сохранять можно только треки Blink** (метка BLINK, `source=blink`), у которых `offline_allowed=true`, при активном Blink+ и входе в аккаунт.
  Остальные источники (Яндекс, SoundCloud, Jamendo, YouTube, парсер) в офлайн не идут: приложение сразу пишет «Этот трек играет только онлайн», а не «не нашло трек 0/1».
- Ссылку на файл даёт резолвер (`/api/offline/resolve`: `url`, `mime`, `bytes`, `etag`, `expiresAt`). Пока его нет на проде, берём `/api/play/:uuid`.
- Скачивание идёт в `<track>.part` кусками по Range (сервер режет открытый Range до 2 МиБ, поэтому цикл до `have == total`), докачивает после обрыва и перезапуска, шлёт `If-Range` с etag дословно, при 403 на файле резолвит заново.
- Файл проверяется до записи (первые байты: ID3/MPEG/ftyp/OggS/fLaC/RIFF, не HTML и не JSON) и после (размер, длительность, длина `.part` равна числу принятых байт). Только потом атомарный commit и запись в манифест.
- Повторы 1/3/9/27 с (±20%). Счёт повторов сбрасывается, если упавшая попытка принесла байты. Без сети попытка не тратится. Отказы (нет Blink+, трек недоступен, битый файл) помнятся 24 часа, «Повторить» их сбрасывает.
- Если файл пропал, а запись в манифесте осталась и в ней есть сам трек, приложение тихо ставит его на скачивание заново (без тоста).
- Ошибки только из контракта: `NO_MATCH`, `NOT_DOWNLOADABLE`, `NOT_ALLOWED`, `SOURCE_ERROR`, `BAD_CONTENT`, `NO_SPACE`, `TIMEOUT`, `CANCELLED`, `NO_NETWORK`. Каждая даёт понятный текст и, где можно, кнопку.
- Файлы лежат в приватной папке приложения (не в галерее и не в «Файлах»).
- Сохранённый трек играет с диска первым, и онлайн тоже. Без сети нужен активный Blink+ (по последней известной дате подписки). Очередь без сети пропускает несохранённые и один раз пишет «Пропущено N: нужен интернет».
- Фон: Android качает в foreground-сервисе с уведомлением и возобновляется после перезапуска; iOS отдаёт передачу в фоновую `URLSession`, которая живёт, пока приложение свёрнуто.
- Один писатель на трек (инвариант I7): один менеджер на процесс, повторное сохранение того же трека ничего не делает.

## Риски и что проверено, а что нет

- **iOS я не компилировал локально** (нет Mac). Проверка только в облачной сборке на macOS, она и скажет, что сломано. Ядро `BlinkCore` дополнительно проверяется тестами на Linux.
- **Скачивание проверено** тестами на локальном сервере-двойнике (Range, обрывы, подмена файла, битые данные, перезапуск). Против настоящего `blinkmusic.cc` с вашим аккаунтом и Blink+ его ещё не гоняли: для этого нужен вход.
- **Резолвер `/api/offline/resolve`** на проде может ещё не стоять. Тогда работает запасной путь `/api/play/:uuid`, но проверки Blink+ и `offline_allowed` только на клиенте.
- **Лицензия на офлайн Яндекс-источника** вне этой задачи: он в офлайн не идёт. Шифрование файлов на диске отложено (поле `enc` в манифесте зарезервировано).
- **Минуты macOS стоят ×10** на бесплатном тарифе GitHub (около 200 в месяц). iOS собираем по ручному запуску.
- **Lumi и Mimose** найти поиском не удалось (по названиям выдаётся не то). «Лучше них во всём» сверяем по скринам, когда они появятся.
- **Бесплатные сертификаты** отзывают без предупреждения. Для нормального релиза нужен Apple Developer.
